What this run establishes

Both recovery scenarios passed.

  1. Two authenticated clients joined the same private match through different workers.
  2. A legal draw received a server acknowledgement.
  3. One worker stopped. The affected client resumed the same match through surviving capacity.
  4. Closing that client's WebSocket triggered another automatic reconnect and state reconciliation.

The report identifies source revisions, configuration, selected state comparisons, and observed intervals.

A foundation for your game

Flutter and Riverpod handle presentation and recovery. Java validates online play. Redis holds live match state, with Pub/Sub for cross-worker fan-out. The reference AWS deployment uses Fargate, ALB, and Terraform.

Game rules and engines follow a plugin architecture. Each game implements its own rules and client experience against the shared runtime.

Commercial source distribution is being prepared. The public repository contains documentation and evidence. Implementation access is provided separately under an agreed commercial license.
